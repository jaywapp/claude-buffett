## 1. 확정된 요구사항

- 저장소 루트는 `D:\\work\\claude-buffett`다.
- Codex와 Claude Code가 선택된 단일 오케스트레이터 규칙을 따르며, 한 작업 트리에서 도구를 혼합하지 않는다.
- 관련 문서는 `docs\\` 아래에 둔다.
- 웹·UX/UI 변경에는 Vercel/Supabase 기본값과 3종 콘셉트 승인 게이트를 적용한다.

## 2. 설계 개요

- 기존 루트 지침 파일은 보존한다.
- 누락된 `AGENTS.md`는 공통 Codex/Claude 프로젝트 계약 템플릿으로 생성한다.
- 누락된 `CLAUDE.md`는 `@AGENTS.md` import와 Claude 전용 협업 메모를 포함한 템플릿으로 생성한다.
- `docs/README.md`는 기존 파일이 없을 때만 추가한다.
- 분석·설계·작업 계획 문서는 이 설정 변경 자체의 근거와 검증 방법을 보존한다.

## 3. 컴포넌트와 데이터 흐름

```text
사용자 지시 → Codex 루트 오케스트레이터 → 저장소별 작업 브랜치
  → 누락 지침/docs 파일 생성 → 정적 검증 → commit → push → PR → 기본 브랜치 병합
```

## 4. 인터페이스·데이터·상태 변경

- API/CLI/UI: 저장소 지침과 문서 파일만 추가한다.
- 데이터 모델·마이그레이션: 없음.
- 오류·재시도·복구: 기존 변경사항·보호 브랜치·병합 충돌이 발견되면 해당 저장소만 중단하고 보고한다.

## 5. 대안과 트레이드오프

| 대안 | 장점 | 단점 | 선택 여부 |
| --- | --- | --- | --- |
| 기존 지침 파일을 공통 템플릿으로 덮어쓰기 | 내용이 일관됨 | 프로젝트 규칙·생성 원본을 훼손할 위험 | 선택하지 않음 |
| 누락 파일만 템플릿으로 추가하고 기존 파일 보존 | 안전하고 점진적 | 기존 파일의 공통 규칙 통합은 후속 작업 필요 | 선택 |
| 저장소 외부 전역 설정만 사용 | 커밋 diff가 없음 | clone·Codex 세션마다 재현성이 낮음 | 선택하지 않음 |

## 6. 보안·호환성·성능

- 보안: 토큰·키·비밀번호·`.env` 값을 읽거나 기록하지 않는다.
- 지원 플랫폼/버전: 저장소의 기존 도구 체계를 변경하지 않는다.
- 성능 및 용량: 문서·지침 파일만 추가하므로 런타임 영향이 없다.

## 7. 검증 전략

- 추가 파일과 기존 파일의 경로·UTF-8 인코딩을 확인한다.
- Git diff에서 요청 범위를 벗어난 파일이 없는지 확인한다.
- 작업 브랜치의 commit, 원격 push, PR 상태와 병합 결과를 GitHub CLI로 확인한다.
